# SIRP-10 offline integration and attack matrix

This map records repository-only evidence. Every scenario uses a temporary local SQLite store and sealed finite test issuers; it imports no live adapter, transport, provider, session store, CrowdSec client, subprocess, or runtime database.

| Scenario | Authority / invariant | Exact test node | Expected terminal state / evidence | Prohibited side effects | Current limitations |
| --- | --- | --- | --- | --- | --- |
| Bounded evidence to classified policy | Broker accepts only redacted projections; classifier ordering is deterministic; policy never grants execution | `test_offline_lifecycle_is_bounded_redacted_and_terminally_evidenced` | Broker evidence reference; policy has `allowed_to_execute=false` | Network, provider query, raw evidence persistence | Synthetic rules and fixtures only |
| Step-up approval then execution acknowledgement | Password plus live TOTP produces a redacted, single-use action-bound grant; command approval persists the matching durable approval before the request binds action/version/scope/policy/gate/idempotency/rollback/expiry | `test_offline_lifecycle_is_bounded_redacted_and_terminally_evidenced` | `approved` version followed by `executed` opaque receipt; `verified=false` | Real CrowdSec, delivery, host command | Fake acknowledgement is not external observation |
| Independent success then rollback | Sealed source binds exact action/receipt/scope; sealed rollback acknowledgement binds exact operation; audit-chain snapshot binds each terminal ref and rejects missing or tampered terminal evidence | `test_offline_lifecycle_is_bounded_redacted_and_terminally_evidenced` | `verified` evidence then `rolled_back` evidence with exact receipt/verification/rollback refs and verified chain | Real verification or rollback transport | In-process test issuer only |
| Unknown verification | Unknown observation blocks closure and persists failure evidence; rollback still requires sealed acknowledgement | `test_unknown_independent_verification_blocks_closure_then_has_rollback_evidence` | `failed` evidence then `rolled_back` evidence | Any automatic closure | No live readback |
| Raw-data injection | Evidence boundary rejects unsafe keys/content before durable creation | `test_broker_rejects_raw_content_before_it_can_create_durable_incident` | Explicit rejection; empty audit history | Raw log/provider/error storage | Tests representative forbidden shape |
| Replay and cross-action approval reuse | Receipt replay cannot invoke an effect twice; step-up grant and durable approval ID cannot approve another action or be reused | `test_execution_replay_is_single_effect_and_never_closes_success`; `test_step_up_and_durable_approval_reuse_are_cross_action_fail_closed` | Same receipt replay; cross-action rejection leaves actions prepared/approved as applicable and no effect counter changes | Second adapter invocation | Process/restart behavior remains covered by SIRP-09 tests |
| Stale version / target substitution / scope expansion | Exact request binding fails closed before effect adapter | `test_bound_request_substitution_and_staleness_never_call_effects` | `blocked`, action remains `approved`, `verified=false` | Any adapter/transport call | Digest-level scope only; no real target |
| Missing step-up | No grant may be consumed without current bound step-up | `test_missing_step_up_and_delivery_failure_are_no_send_no_effect_boundaries` | Explicit authorization rejection | Approval mutation from missing grant | Browser/session integration remains SIRP-05 scope |
| Delivery failure | Delivery interface is dry-run/no-send and bounded | `test_missing_step_up_and_delivery_failure_are_no_send_no_effect_boundaries` | `blocked_no_send`, no retry scheduling | External delivery | No delivery provider exercised |
| Verifier failure/unknown/unavailable | Only verification can set success; failure and unknown never close; unavailable is normalized to unknown evidence | `test_verifier_failure_unknown_or_unavailable_never_sets_verified_or_closure_success` | `failed`, `closure_blocked=true` | Follow-on success claim | Live independent observer unavailable |
| Sealed authority forgery | Verification issuers, observations, and rollback acknowledgements cannot be constructed, copied, serialized, or revived; an execution acknowledgement cannot claim verification | `test_sealed_issuers_and_receipts_cannot_be_forged_copied_serialized_or_rewrapped` | Content-free rejection | Source or rollback invocation through forged authority | In-process identity sealing only |

Not covered by this slice: any action-specific live Go, real provider/host/session/CrowdSec mutation, external delivery, cross-process rollback mutual exclusion, production deployment, or temporal closure.
