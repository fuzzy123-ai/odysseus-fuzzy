# 1.0 Evidence Release Checklist

Stand: 2026-06-16

Status: **aktive 1.0-Abschluss- und Bugfix-Checkliste**

Dieses Dokument ist der konkrete Startpunkt fuer das `1.0.0` Evidence Release. Es ersetzt keine Detailplaene, sondern zieht den pruefbaren Stand aus Memory-first, Obsidian Lens, Model Router, Scale Foundation und Lightweight Maintenance in eine Go/No-Go-Sicht zusammen.

## Ziel

`1.0.0` wird erst freigegeben, wenn der aktuelle Fork nicht nur "feature-complete" wirkt, sondern reproduzierbar belegbar ist:

- Install-/Startpfad ist nachvollziehbar.
- Provider-/Fallback-Verhalten ist erklaert und getestet.
- Memory-/Obsidian-Lens-Pfade sind intern belegt.
- Rebuild-/Import-/Export-/Upgrade-Evidence ist dokumentiert.
- Bekannte Grenzen sind bewusst akzeptiert.
- Keine offenen P0/P1-Release-Blocker bleiben unbenannt.

## Manuelle Release-Evidence

Diese Punkte sind bewusst manuell. Sie duerfen nicht still als "gruen" markiert werden, nur weil Unit-Tests gruen sind.

Runbook: `docs/plans/1.0-manual-release-evidence-runbook.md`

Aktuelles Evidence-Log: `docs/plans/1.0-manual-release-evidence-log.md`

| Gate | Erwartete Evidence | Go/No-Go |
| --- | --- | --- |
| Fresh install | frischer Checkout, Abhaengigkeiten installiert, Odysseus startet, Obsidian Plugin laedt | Go nur mit Datum, Commit und kurzem Ergebnis |
| Upgrade path | bestehender Checkout wird auf aktuellen `fuzzy/dev` Stand aktualisiert, Plugin/Routen starten weiter | Go nur mit dokumentiertem Ausgangs- und Zielcommit |
| Provider proof | Default-Modell, Fallback-Modell und lokales/DeepSeek-Szenario einmal real konfiguriert oder bewusst als nicht verfuegbar markiert | No-Go, wenn Fallback-Verhalten nicht erklaerbar ist |
| Export/Import/Rebuild | leerer oder Test-Vault kann export/import/rebuild-proof durchlaufen | No-Go, wenn Datenverlust oder stille Source-Writes auftreten |
| Known Limits Review | Grenzen fuer Postgres-Migration, Nextcloud, Qdrant/Kuzu, UMAP/GMM/adRAP, kleine Maintenance-Modelle dokumentiert | Go nur, wenn keine Grenze als fertiges Feature verkauft wird |

## Go/No-Go-Notiz

Aktueller Stand: **intern release-candidate-ready; automatisiertes REL1-Gate am 2026-06-17 frisch gruen; Fresh Install und Upgrade Path manuell belegt; No-Go fuer externes 1.0 Release bis Provider- und Test-Vault-Gates belegt sind.**

Grund: Der interne Feature-/Proof-Stand ist stark und die automatisierten Gate-Gruppen sind frisch gruen (`235 passed, 44 warnings`). Der aktuelle manuelle Lauf belegt Fresh Clone, frischen Start, Plugin-Load, echten Upgrade-Fast-Forward, laufende App-Shell, Auth-Schutz fuer Datenrouten und Known Limits. Offen bleiben ein modellgestuetzter Provider-/Fallback-Antwortlauf mit ready Query-Index sowie ein Export-/Import-/Rebuild-Lauf gegen einen kleinen Test-Vault. Das ist kein Feature-Blocker, sondern die letzte Release-Freigabehandlung.
