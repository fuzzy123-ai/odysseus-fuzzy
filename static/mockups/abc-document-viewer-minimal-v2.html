Coding Lane Notes

The document viewer should stay quiet. Its first job is to show the current document with enough space, contrast, and stability that reading and editing do not feel like working inside a dashboard.

All surrounding workflows can live elsewhere later: file selection, code tools, AI actions, review states, and inspector panels. This surface is only the document itself.

Viewer Principle

  • No visible file browser.
  • No toolbar, search, inspector, metadata rail, or window header.
  • The document should fill most of the available screen.
  • Content may be text, markdown, code, PDF, image, or another supported document type.

Code Inside A Document

Code is still document content here. Execution, diagnostics, and commits can be layered in later, but the first visual pass should not imply a full IDE. 

def render_document(document):
    # viewer only displays the current document
    content = document.content
    return display(content, mode=document.type)
